# Memory

### 🧠 Learned Invariants & Failure Post-Mortems

- **[26-10-20 · Scene / character pose]**: Workers rendered standing next to their desks → **Root cause**: new characters spawned at the lounge and walked to their station, but the walk step is frame-rate bound (`WALK_SPEED * delta` with `delta` capped at 0.06), so on a software renderer they never arrived and `setSitting` was only called inside the arrival branch. → **Invariant Rule**: spawn a character at its destination station on first sync, and never let pose state (sitting/walking) depend on a movement loop that may not converge.

- **[26-10-20 · Scene / tick]**: Animation stuttered and walking stalled on slow tabs → **Root cause**: `delta` was clamped to 0.06 s, so a 3 fps frame advanced only 0.06 s of the world per frame. → **Invariant Rule**: clamp frame delta to the largest value that still prevents teleporting (0.15 s here), and keep time-scaled motion out of the clamped region.

- **[26-10-20 · Web search]**: `web_search` returned zero results on every query → **Root cause**: `lite.duckduckgo.com` answers datacenter IPs with HTTP 202 and a bot-challenge page, so the `result-link` selector never matched. → **Invariant Rule**: treat an empty parse as a provider failure, not an answer, and chain keyless providers (DuckDuckGo HTML POST, then Bing RSS) before surfacing an error.

- **[26-10-20 · Tool loop / model protocol]**: The model emitted native tool-call markup instead of the JSON action the prompt asked for, so actions never ran → **Root cause**: the provider speaks OpenAI function calling; instructing JSON in the prompt fights the wire protocol. → **Invariant Rule**: advertise real `tools` schemas and consume `tool_calls` deltas; keep the JSON-action parser only as a fallback for endpoints that reject `tools`.

- **[26-10-20 · Sandbox]**: Allowlisted binaries could still be pointed outside the workspace → **Root cause**: the command allowlist validated the binary but not its arguments, and `cwd` is not a boundary. → **Invariant Rule**: validate every argument token (`..` hops, absolute paths) against the workspace root in addition to the binary allowlist, and never claim a shell is jailed when it is only checked.

- **[26-10-20 · Mission roll-up]**: The lead started reconciling while a queued subtask was still running → **Root cause**: `create_task` recorded the *immediate* task as parent, so work a subtask delegated lived one level below the mission and never counted in "is the team done?". → **Invariant Rule**: roll delegated work up to the mission root (`mission ? taskId : parent.parentId ?? taskId`), and always derive "everyone finished" from that root.

- **[26-10-20 · Client bootstrap]**: The office sat on "Connecting…" forever after one failed `/api/session` → **Root cause**: bootstrap fetched once, swallowed the error, and then subscribed; nothing retried and the empty state rendered as a permanent loading state. → **Invariant Rule**: subscribe to the stream that carries a full snapshot *first*, and give the initial fetch bounded retries — a UI must never have a terminal loading state.

- **[26-10-20 · Verification tooling]**: `pkill -f "server/src/index.ts"` killed the very shell running the command, silently aborting a verification chain → **Root cause**: `pkill -f` matches full command lines, including the shell whose `-c` string contains the pattern. → **Invariant Rule**: when killing by pattern, use a regex that cannot match its own command line (`src/inde[x].ts`), or kill the listener PID from `ss -ltnp`.

- **[26-10-20 · Completion gate]**: A task showed `done` in the UI while its checks were still running → **Root cause**: the `complete_task` handler flipped the status first and the runtime ran verification afterwards, so every observer (board, CLI poll loop) saw success before validation finished. → **Invariant Rule**: run a gate *before* mutating the state it guards; never let an observable transition happen ahead of its validation.

- **[26-10-20 · `speak` tool]**: A mission that had built the whole site ended as `blocked` → **Root cause**: `speak` returned `followUp: false`, so a decorative speech bubble terminated the turn and the still-`doing` task fell into the blocked branch. → **Invariant Rule**: only `complete_task` may end a task turn; cosmetic tools must keep the loop alive whenever a task is attached.

- **[26-10-20 · `read_file` window]**: `read_file` answered with a single line → **Root cause**: a `limit` of `0` was clamped up to 1 instead of falling back to the default window. → **Invariant Rule**: treat zero/negative paging values as "use the default", and clamp only after the default has been chosen.

- **[26-10-20 · CLI boot / session readiness]**: `aegisxworker "…"` ran the mission in demo mode even though a valid key was loaded → **Root cause**: `GET /api/session` answers as soon as Express listens, but the boot-time `connect()` is awaited afterwards, so the first snapshot still reports `configured: false` / `demoMode: true` and the CLI trusted it. → **Invariant Rule**: any consumer that branches on connection state must poll until `settings.configured` flips (bounded timeout), never branch on the first successful HTTP response.

- **[26-10-20 · CLI config]**: The launcher did not see `OFFICE_API_KEY` from `.env` → **Root cause**: `--env-file` is passed to the *child* server process, so the parent CLI's `process.env` stays empty. → **Invariant Rule**: resolve config in one place — the CLI only decides flags, the server owns env loading; the CLI detects a key with `existsSync('.env')` instead of reading `process.env`.

- **[26-10-20 · Verification]**: Background restarts silently failed and the old process kept serving → **Root cause**: `kill <wrapper pid>` left the real `node` child alive, so the new server died with `EADDRINUSE` while tests ran against stale code. → **Invariant Rule**: confirm the listener PID via `ss -ltnp` after every restart, and verify the new code path (e.g. a changed log line) before trusting a green test run.

- **[26-10-21 · Token meter]**: Per-task spend would have drifted from per-agent spend if each side kept its own counter → **Root cause**: `tokensUsed` was written by two call sites (real turn, demo turn) and a task had no counter at all, so any new call site could book a turn on one side only. → **Invariant Rule**: book usage in exactly one place (`OfficeStore.recordUsage`) that moves the worker *and* the task together, and derive every roll-up (mission, summary, UI) from that single field.

- **[26-10-21 · Mocked multi-agent test]**: A scripted lead wrote the deliverable instead of delegating → **Root cause**: the mock matched a substring of the mission *detail* (`Build the UI and the API…`) rather than the subtask title on the brief's first line. → **Invariant Rule**: when scripting a model, branch on the exact brief field you control (`Task: <title>` first line), never on a substring that the operator's prompt can also contain.

- **[26-10-21 · Mission restore]**: A restored board could have looked alive while nothing was running → **Root cause**: `doing` is a statement about a live process, and persistence alone brings the label back without the process. → **Invariant Rule**: on boot, settle every `doing` task to `blocked` with a reason before serving the first snapshot; never auto-run a restored task (that silently re-bills) and never leave a worker marked busy.

- **[26-10-21 · Shared test state]**: Two suites chained in one shell passed alone and failed together → **Root cause**: both inherited the same `OFFICE_STATE_DIR`, so the second suite restored the first one's board. → **Invariant Rule**: every suite that boots the office must own a fresh state directory; shared persistent state turns independent tests into an order-dependent chain.

- **[26-10-21 · Per-step cost]**: Attributing token cost to individual tool calls would have inflated every total → **Root cause**: an endpoint bills a model round trip, and one round can emit several tool calls, so splitting or repeating the round's usage per call double-counts. → **Invariant Rule**: cost the *round*, log one step line per round, and assert in a check that the step bills sum to the task total.

- **[26-10-21 · History roll-up]**: A daily cost total could count a subtask twice → **Root cause**: the history walked every finished task, while a mission's total already includes its subtasks. → **Invariant Rule**: group by the root that owns the spend (mission root, or a standalone task), and skip any task with a `parentId` when building totals.

- **[26-10-21 · Panel tabs]**: A hidden `[hidden]` tab kept rendering its flex layout → **Root cause**: a class rule (`display: flex`) outranks the user-agent `[hidden] { display: none }`, so the Activity list stayed visible behind the Costs tab. → **Invariant Rule**: any element toggled by the `hidden` attribute that also sets `display` needs its own `[hidden] { display: none }` rule.

- **[26-10-21 · Verification harness]**: The README's main regression commands pointed at `/tmp/pw/*.mjs` and those files were gone, so the gate, checkpoint, tool jail and renderer had no re-runnable proof → **Root cause**: the harness was written in a scratch folder instead of the repo, so no path in the documentation was tied to a file that survives a temp cleanup. → **Invariant Rule**: every command a doc tells someone to run must live under `scripts/` behind an npm script; a harness in `/tmp` is a scratch run, not coverage — and check the *failure* paths, since the happy path is already exercised by the live-server run.

- **[26-10-21 · Project memory]**: A fact learned in mission A was written *after* the task flipped to `done`, so the CLI could exit with the write still in flight and lose it → **Root cause**: the write hung off the observable transition instead of preceding it; `complete_task` mutates status inside `executeAction`, and anything after that awaited return is racing the consumer. → **Invariant Rule**: write side effects that must accompany a completion *before* the status mutation (gate → memory → done), never after — the same ordering rule the completion gate already follows.

- **[26-10-21 · Workspace isolation]**: A harness could have run its fixtures inside the operator's real project → **Root cause**: `loadSavedRoot()` read a hard-coded `.agent-office/workspace.json` at boot and overwrote `OFFICE_WORKSPACE`, so the caller's explicit folder was silently discarded on any machine that had used the app before. → **Invariant Rule**: an explicit environment pin always beats stored state, and persisted state must be read from `STATE_DIR` so a caller that owns a state folder also owns its saved values; any harness that writes files must verify the server's reported workspace before creating a task.

- **[26-10-21 · Eval acceptance]**: An acceptance check failed with `files is undefined` / `mutated.write is not a function` while the mission itself looked fine → **Root cause**: the check's context was assembled from the folder helpers only, so task-specific data and mutation helpers were assumed rather than supplied. → **Invariant Rule**: give a check one explicit context built in one place (folder helpers + fixture files), and let a copy of the workspace hand back the same shape — an acceptance test is code and needs its own contract.

- **[26-10-21 · Eval verdict]**: A harness that trusts the office's `done` would have scored 10/10 on work that was not done → **Root cause**: the runtime's completion gate only runs checks the folder declares, so a hard-coded colour, a test that only covers the empty case and a needless rewrite all pass it. → **Invariant Rule**: the eval verdict comes only from a check that reads and runs the artefact itself, and the harness's own test must include scripted work that is *wrong on purpose* to prove the check can fail.

- **[26-10-21 · Delegation in the eval]**: A scripted lead would have replayed its planning pass forever → **Root cause**: the reconciliation pass re-runs the same task title with a *fresh* conversation, so a mock keyed on title + tool-round restarted at round 0 and issued `create_task` again instead of reconciling. → **Invariant Rule**: for any agent re-run for a second pass, the scripted model must branch on the brief that announces the pass (`This is pass 2`), because the conversation restarts and the title does not change.

- **[26-10-21 · Mission reconciliation]**: A task with subtasks never reconciled unless it was created through the mission endpoint → **Root cause**: `#maybeSynthesise` returns early unless `task.mission` is set, and `/api/tasks` leaves it false while `/api/missions` sets it and appends the lead brief. → **Invariant Rule**: delegation is a property of how the task was created, so anything that exercises the lead's second pass must use `/api/missions`; a plain task with `parentId` children is a plan that silently never finishes.

- **[26-10-21 · Delegated cost]**: A mission's spend could look correct while omitting the teammate who did the work → **Root cause**: the board bills each task separately, and the mission total only includes the child when the roll-up walks `parentId`. → **Invariant Rule**: assert the mission total is *greater* than the lead's own usage in any test of delegation — otherwise a broken roll-up and a working one produce identical numbers.

- **[26-10-21 · Blocked tasks]**: A turn that ended in prose or hit one 500 killed the mission → **Root cause**: `blocked` was the only terminal state for five different conditions, and nothing inside the turn retried or asked again, so a recoverable moment needed a human. → **Invariant Rule**: recover inside the turn first (retry a transient error once, nudge a silent worker once) and only then block; a status that can only be cleared by hand must never stand in for "the model stopped talking".

- **[26-10-21 · Billing a failed turn]**: Tokens burned by a turn that threw were missing from the meter → **Root cause**: `recordUsage` sat on the success path after the loop, so the `catch` that marks the task blocked skipped it entirely. → **Invariant Rule**: record spend in `finally` and key it off the accumulated usage, never off reaching the end of the function; a blocked task that shows zero cost is a lie the operator will act on.

- **[26-10-21 · Translation completeness]**: A half-translated UI passes typecheck and build → **Root cause**: keys are looked up at runtime, so a missing key or an untranslated cell renders English inside an Indonesian screen with no error. → **Invariant Rule**: derive the key type from one table, tag static markup with `data-i18n`, and check the two columns plus key usage in a script — the compiler cannot see an HTML attribute.

- **[26-10-21 · Native tool observations]**: Workers re-read the same files and kept probing instead of working, and a live log was full of "Command failed" lines → **Root cause**: `#observation` serialized only `status/summary/next_actions/artifacts` on the native tool-call path, while file contents, command output and gate details live in `detail`; the JSON-action fallback appended `detail`, so the two protocols disagreed and only the fallback could actually read a file. → **Invariant Rule**: every protocol a model can use must serialize the same observation shape; if tool handlers treat a field as the payload, it has to be on the wire, and the check must exercise the native path rather than the fallback.

- **[26-10-21 · Completion gate / housekeeping]**: A finished mission left `probe-*.js` and `qa-*.mjs` in the folder, and later workers tripped over them → **Root cause**: the prompt asked for cleanup, but nothing in the gate read the folder; a rule that exists only as prose is advisory. → **Invariant Rule**: pair every "delete your scratch files" instruction with a name rule the gate enforces (`server/src/scratch.ts`), ask a bounded number of times and then record the leftovers — never delete a worker's files on its behalf, and never loop on housekeeping.

- **[26-10-21 · Sandbox shell]**: Workers lost whole turns to `Command rejected: ">" is not allowed in the sandbox`, then retried the same redirect in another form → **Root cause**: the sandbox refused shell grammar instead of executing it, and the refusal named no replacement, so the model's habit (`echo x > f`, `cmd | grep`, `a && b`) had nowhere to go; `sh -c` was ruled out because it re-opens injection. → **Invariant Rule**: parse shell grammar yourself and execute argv arrays (`server/src/shell.ts`) — pipes, redirects, `2>&1` and `&&`/`||`/`;` must work, every path and redirect target must still resolve inside the workspace, and a refusal must name the tool that replaces the binary (`curl` → `http_check`, `rm` → `delete_file`).

- **[26-10-21 · Shell exit status]**: `grep zzz file` reported a failure with "no matches" in the same result → **Root cause**: the per-statement "no match is a result" rule was applied inside `runStatement`, but `runShell` recomputed `ok` from the final exit code and discarded it. → **Invariant Rule**: carry the statement's own verdict up through a chain, and assert the transport layer's answer in a check — a rule that is computed and then overwritten is indistinguishable from one that was never written.

- **[26-10-21 · Failure ledger]**: "Missions keep failing" could not be acted on because `blocked` was one status for six causes and the detail was prose → **Root cause**: each failure path wrote `status: 'blocked'` itself, so nothing forced a cause and nothing could rank them. → **Invariant Rule**: route every blocked write through one function that requires a reason code, keep the ranking in a shared pure function the board and the API both read, and let a check fail the build when a new blocked write appears without a cause.

- **[26-10-21 · Jail probe]**: `bwrap` reported available but every command silently ran unjailed → **Root cause**: the status probe tested `existsSync('/usr/bin/bwrap')`, and the first real probe bound only `/usr`, so a dynamic binary failed to find its loader and the jail was marked unusable — the fallback was correct but the diagnosis was wrong. → **Invariant Rule**: a capability probe must run the same minimal environment the real path uses (same binds, cleared env) and must report the failure reason, never a boolean derived from a file existing.

- **[26-10-21 · Jail vs. process group]**: a jailed dev server would survive `stop_process` → **Root cause**: `--new-session` puts the child in its own session, while `stop_process` signals `-pid` on the sandbox's group. → **Invariant Rule**: a supervisor that owns a long-lived child must share its process group (drop `--new-session` when there is no TTY), and the check must start a real server, hit its port, stop it, and prove the port is closed.

- **[26-10-21 · Auto-remedy boundary]**: Automatically running the tool a refusal suggested is a repair for reads and a hazard for writes → **Invariant Rule**: the runtime may auto-run only read-only remedies (`http_check`, `port_status`, `preview_screenshot`); a refused `rm` offers `delete_file` but still requires the model to ask, and the remedy budget per turn is small enough that it cannot become a second loop.

- **[26-10-21 · Policy gate]**: `npm run check:usage` timed out because the mocked model's `complete_task` never finished the task → **Root cause**: the new gate denied every action outside a read-only list when `OFFICE_TOOLS=0`, and `complete_task` is not a file tool, so the board could never move without file access. → **Invariant Rule**: a permission gate must classify actions by the capability they actually need — office actions (move, status, note, create/complete task) are always allowed; only file, shell, process, preview and network tools depend on the operator's switches, and one check must run those actions with tools disabled.

- **[26-10-21 · Task dependencies]**: `createTask` with `dependsOn` would have thrown at runtime while filtering ids → **Root cause**: the filter closure compared against `task.id` inside the object literal that was still being constructed (TDZ). → **Invariant Rule**: generate the id into a binding before building the record and filter against that binding; a self-reference check inside an initializer is a construction-order bug every time.

- **[26-10-21 · Capability router]**: Mengirim 29 skema tool tiap round = ~4.000 token sebelum satu file dibaca → **Root cause**: `buildToolSchemas` hanya tahu izin operator, bukan fase pekerjaan, sehingga tidak ada yang bisa memangkas permukaan tool. → **Invariant Rule**: setiap router fase wajib (a) menyertakan aksi office inti di semua fase agar worker selalu bisa selesai, (b) tidak pernah menaruh tool tulis/jail di fase `inspect`, dan (c) diuji dengan pengukuran token skema pada urutan misi nyata — bukan dengan menghitung jumlah tool.

- **[26-10-21 · Reviewer]**: Sebuah review yang balasannya tidak bisa diparse tidak boleh dianggap lulus → **Invariant Rule**: parser verdict mengembalikan `null` untuk JSON rusak, verdict tak dikenal, atau `fail` tanpa alasan; runtime mencatatnya sebagai warn dan melanjutkan hanya karena check folder sudah lulus — bukan karena reviewer "setuju".

- **[26-10-21 · Multimodal]**: Base64 gambar di dalam observasi JSON akan memakan ribuan token dan tetap tidak terlihat model → **Invariant Rule**: media dikirim sebagai `image_url` content part pada pesan berikutnya, sementara observasi JSON hanya berisi path dan ringkasan; satu check harus membuktikan wire format-nya, bukan sekadar file terbaca.

- **[26-10-21 · Write locks]**: Dua worker menulis file yang sama tanpa error apa pun, dan edit salah satunya hilang → **Root cause**: tidak ada kunci per-path; tiap panggilan hanya meng-`await` filesystem, jadi tulisannya berselang dan yang terakhir menang. → **Invariant Rule**: setiap aksi yang mengubah file harus mengambil kunci all-or-nothing sebelum efek samping dan melepasnya di `finally`; penolakan wajib menyebut pemegang kunci, dan check harus membuktikan hanya satu dari dua tulis bersamaan yang mendarat.

- **[26-10-21 · Argument validation]**: `priority: "urgentt"` diterima sebagai `ok: true` dan menjadi `medium` → **Root cause**: pembaca argumen memakai default senyap, sehingga salah ketik terlihat seperti sukses dan model tidak pernah belajar nilainya salah. → **Invariant Rule**: validasi argumen terhadap JSON schema yang sama yang dikirim ke model, tolak `invalid_args` dengan nama field + nilai yang sah, dan jangan pernah mengoerce enum diam-diam.

- **[26-10-21 · Vision critic]**: Screenshot yang tidak pernah dinilai membuat halaman "lulus check" tetapi rusak secara visual → **Invariant Rule**: critic visual memakai kontrak yang sama dengan reviewer kode (balasan tak terbaca = `null`, `fail` tanpa isu = tidak valid, maksimal satu penolakan), dijalankan setelah gate dan reviewer, dan diuji lewat misi nyata dengan gambar benar-benar terlampir.

- **[26-10-21 · Stale reads]**: Kunci per-panggilan tetap membiarkan lost update: A baca, B tulis, A tulis salinan lamanya → **Root cause**: kunci hanya melindungi durasi tulis, bukan kesegaran isi yang dibaca. → **Invariant Rule**: simpan hash isi setiap file yang dibaca per worker, tolak mutasi dengan `stale_read` bila hash berubah, dan perbarui hash setelah setiap tulis sukses — optimistic concurrency, bukan kunci panjang.

- **[26-10-21 · Merge gate]**: Task bisa ditandai `done` setelah file terverifikasinya diubah worker lain saat reviewer berjalan → **Root cause**: verifikasi dan penandaan selesai dipisahkan oleh panggilan model yang memakan waktu, tanpa memeriksa ulang pohon. → **Invariant Rule**: hash file yang ditulis task tepat setelah check lulus, lalu bandingkan lagi di gerbang merge di bawah antrean; jika berbeda, kirim balik untuk check ulang, jangan klaim hijau.

- **[26-10-21 · Observation shape]**: `next_actions` yang salah ketik membuat model meminta tool yang tidak ada, dan ringkasan kosong membuatnya mengulang panggilan → **Invariant Rule**: validasi bentuk hasil tool sebelum menjadi konteks model; perbaiki di satu tempat (`outputGuard.ts`), catat sebagai warn, dan uji bahwa hasil tool asli semuanya lolos.

- **[26-10-21 · Per-tool result contract]**: `ok: true` dengan `summary` rapi bisa berarti model menerima "Read app.ts (lines 1-40)" tanpa satu baris isi, atau "gambar terlampir" tanpa gambar → **Root cause**: guard hanya memeriksa bentuk observasi, bukan apakah payload yang dijanjikan tool benar-benar ada. → **Invariant Rule**: setiap tool mendeklarasikan apa yang diutang sebuah **sukses** (`server/src/resultSchemas.ts`), penolakan tidak diwajibkan membawa payload, pelanggaran diubah menjadi observasi `error` di `buildObservation` (bukan diteruskan sebagai sukses), dan `check:outputs` wajib menjalankan tool nyata terhadap kontraknya sendiri.

- **[26-10-21 · Docs rot]**: README tetap terlihat rapi sementara sembilan modul `server/src` hilang dari peta file, dan ROADMAP sempat menyebut check yang tidak ada → **Root cause**: dokumentasi tidak pernah dieksekusi, jadi kebenarannya bergantung pada ingatan penulis terakhir. → **Invariant Rule**: perlakukan peta file dan baris bukti sebagai kontrak yang diuji (`check:docs`): dua arah untuk peta, dan setiap `check:…` yang diklaim harus ada di `package.json` sekaligus di rantai `npm run check` — atau terdaftar eksplisit sebagai check manual beserta alasannya.

- **[26-10-21 · Map parser]**: peta file sempat dilaporkan lengkap padahal `src/preview.ts` tidak terbaca karena barisnya hanya satu spasi dari deskripsi → **Root cause**: regex pemindai menuntut dua spasi, jadi entri yang tidak sejajar kolom menjadi tidak terlihat dan check melaporkan hasil palsu. → **Invariant Rule**: parser dokumentasi harus menerima bentuk yang benar-benar dipakai (satu spasi cukup), dan check pemindai wajib punya fixture negatif yang membuktikan ia mendeteksi kerusakan.

- **[26-10-21 · Worktree per task]**: Dua worker bisa membaca waktu berbeda lalu menulis satu file; kunci per-panggilan dan `stale_read` tidak menolong karena keduanya menjaga waktu, bukan identitas → **Root cause**: semua task berbagi satu pohon, jadi tidak ada tempat untuk menahan perubahan sebelum disetujui. → **Invariant Rule**: beri tiap task checkout git sendiri (HEAD + file yang belum di-commit sebagai baseline commit detached), landing hanya lewat `mergeQueue` dengan perbandingan hash per file, konflik dilaporkan per nama file lalu salinan worker disegarkan dan versi lamanya disimpan, dan checkout task yang blocked harus dipertahankan — menghapusnya berarti office menghancurkan satu-satunya salinan pekerjaannya.

- **[26-10-21 · Refresh vs stale guard]**: Setelah landing ditolak, menyalin teks folder ke checkout membuat `stale_read` memblokir percobaan ulang worker yang sah, lalu `complete_task` berikutnya "berhasil" dengan nol perubahan → **Root cause**: tracker menyimpan hash yang kita sendiri ubah di belakangnya, dan gerbang merge tidak membedakan "tidak ada yang perlu di-landing" dari "perubahan worker hilang". → **Invariant Rule**: setiap kali office menulis ulang file milik worker, `forgetRead` untuk path itu; dan setelah konflik, sebuah task tidak boleh selesai sampai ada perubahan yang benar-benar ter-landing.

- **[26-10-21 · Log kind scan]**: menyatukan dua `kind` log dalam satu ternary (`built.contractViolated ? 'agent.contract' : 'agent.output'`) membuat `check:wording` melaporkan `agent.output` sebagai template mati → **Root cause**: pemindai mengambil literal pertama yang berbentuk kind di jendela `appendLog(`, jadi satu panggilan hanya terhitung satu kind. → **Invariant Rule**: tulis satu `appendLog` per kind dengan literalnya sendiri, jangan memilih kind lewat ekspresi, dan jalankan `check:wording` setiap kali menambah kind log.

- **[26-10-21 · Reviewer hanya untuk folder non-git]**: Reviewer independen melewatkan setiap folder yang sudah repo, karena ia hanya punya diff dari checkpoint — jadi di folder operator (kasus normal) lapisan review tidak pernah berjalan, tanpa satu pun tanda di log → **Root cause**: sumber diff diikat ke satu mekanisme (checkpoint) yang justru sengaja dimatikan untuk repo. → **Invariant Rule**: setiap jenis folder harus punya sumber diff untuk reviewer (checkpoint untuk folder biasa, checkout task untuk repo), dan `check:review` wajib punya misi nyata di repo git tanpa checkpoint.

- **[26-10-21 · Artefak office ikut ter-landing]**: Dengan worktree, `preview.ts` menulis `.agent-office/previews/*.png` di dalam checkout, lalu landing menyalinnya ke folder operator dan dua task yang mem-preview halaman sama berebut path yang sama → **Root cause**: landing memakai `git diff` mentah tanpa membedakan deliverable task dari state milik office. → **Invariant Rule**: path milik office (`.agent-office/`, `.aegisx/`) dikecualikan dari landing **dan** dari diff reviewer, dan check harus membuktikannya dengan file preview nyata.

- **[26-10-21 · Cache prefix vs identity]**: Klaim "blok prompt yang dibagi semua worker byte-identik" ternyata salah sejak awal — `You are {name}, a {role}` ada di karakter pertama, jadi prefiks setiap worker berbeda di huruf kelima dan cache provider tidak pernah kena → **Root cause**: identitas pekerja ditulis di dalam konstanta instruksi bersama, dan `check:prompt` hanya membandingkan ukuran, tidak pernah membandingkan prompt dua worker. → **Invariant Rule**: nama dan peran tidak boleh muncul di prefiks bersama (identitas ditaruh setelah pak peran), dan check wajib membangun prompt untuk dua peran berbeda lalu gagal bila potongan bersamanya berbeda satu byte.

- **[26-10-21 · Role pack matching]**: Pak "Product Manager" tidak pernah terpakai karena kata `manager` ada di daftar match pak lead yang diperiksa lebih dulu → **Root cause**: pencocokan peran memakai daftar kata yang tumpang tindih tanpa aturan urutan, sehingga pak yang lebih umum menelan pak yang lebih spesifik dan pak spesifik menjadi kode mati. → **Invariant Rule**: setiap pak harus reachable dari labelnya sendiri (`resolveRolePack(pack.label).id === pack.id`) dan itu diuji, bukan diasumsikan; kata yang terlalu umum (`manager`, `engineer`, `dev`) tidak boleh menjadi pemicu.

- **[26-10-21 · Mock routing by substring]**: Tiga check misi nyata (`check:review`, `check:merge`, `check:worktree`) berubah jadi timeout begitu doktrin tim menyebut "independent reviewer", karena mock mengenali panggilan reviewer dengan `system.includes('independent reviewer')` dan setiap prompt worker kini memuat frasa itu → **Root cause**: test double mengklasifikasi request dari potongan teks yang bisa muncul di prompt lain, bukan dari kalimat pembuka perannya sendiri. → **Invariant Rule**: kenali peran sebuah prompt dari awalan yang unik (`startsWith('You are the independent reviewer')`), dan setiap kali teks prompt bersama ditambah, jalankan ulang check yang memakai model mock.

- **[26-10-21 · Brief gate counted adjectives]**: Gate brief menolak "Polish things" tetapi meloloskan "Fix the retry: it must stop and should be verified" — karena kata penerimaan (`must`, `verified`) ikut dihitung sebagai anchor → **Root cause**: `found` menggabungkan anchor dan kata sifat dalam satu daftar, lalu kelulusan diuji dengan `found.length === 0`. → **Invariant Rule**: pisahkan `anchors` dari penanda kualitas; kelulusan hanya dari anchor (path, perintah, endpoint, literal backtick, objek SQL, atau "no file changes"), dan uji kasus "kata penerimaan saja harus ditolak".

- **[26-10-21 · Anchor patterns vs bahasa sehari-hari]**: Pola perintah `\b(make|go|node|git)\s+\w+` membuat "make the product better" lolos sebagai perintah build → **Root cause**: nama tool adalah kata kerja biasa juga, dan regex tidak membedakan keduanya. → **Invariant Rule**: nama runner hanya dihitung di dalam backtick atau saat diikuti subcommand yang dikenal; setiap anchor baru wajib diuji dengan satu kalimat pemasaran yang tidak boleh lolos.

- **[26-10-21 · Yardstick yang hanya mencari teks]**: `accept` misi mobile menerima layar yang state error-nya sudah tidak mungkin tercapai (`if (false)`) karena hanya mencari string `'Could not load orders'` → **Root cause**: acceptance memeriksa copy yang dirender, bukan apakah state itu benar-benar dibaca dari state. → **Invariant Rule**: setiap yardstick wajib punya `breakIt` yang realistis dan `check:playbook` menuntut yardstick menolaknya; untuk UI, periksa guard state (`state.error`), bukan hanya teksnya.

- **[26-10-21 · Fixture sintetis vs field baru]**: `check:eval` gagal karena fixture "handoff salah worker" membangun child task tanpa `pack`, sehingga assertion baru menembak lebih dulu daripada assertion spend yang sedang diuji → **Root cause**: fixture sintetis tidak diperbarui saat kontrak `Task` bertambah, jadi ia menguji field yang salah. → **Invariant Rule**: setiap kali `Task` mendapat field wajib baru, perbarui board sintetis di check (jangan melemahkan assertion yang baru), dan biarkan fixture tetap meniru objek nyata.

- **[26-10-22 · Pack dari sinyal pertama]**: Peran generik memilih pak dari sinyal pertama yang cocok, jadi brief "migrasi data, lalu rapikan site/index.html" divonis Data padahal artefak yang benar-benar akan ada adalah file HTML → **Root cause**: inferensi memakai `pattern.test()` per sinyal (boolean) lalu mengambil elemen pertama, sehingga urutan deklarasi — bukan kekuatan bukti — yang menentukan. → **Invariant Rule**: beri bobot eksplisit (artefak 3, kata pertama 1, kata kedua 1, satu sinyal tidak bisa menang hanya karena lebih dulu dideklarasikan), dan kembalikan `{pack, source, evidence}` agar setiap pilihan bisa dibantah.

- **[26-10-22 · Pak dipilih dua kali]**: Prompt dan reviewer sama-sama memanggil `resolvePackFor`, jadi setelah inferensi diberi bobot keduanya bisa berbeda pendapat tentang bar yang dipakai — tanpa satu pun tanda di layar → **Root cause**: pilihan pak diturunkan ulang di setiap pembaca, bukan disimpan sebagai fakta task. → **Invariant Rule**: selesaikan pak sekali saat task mulai, simpan di `Task.activePack`/`packSource`, dan prompt, reviewer, kartu serta log hanya membaca field itu.

- **[26-10-22 · Template log diuji dengan sampelnya sendiri]**: Perbandingan baris log vs template yang memakai `sampleLine` hanya membuktikan template cocok dengan dirinya sendiri; nilai nyata (`pack: 'data'`) tetap bisa berbeda dari sampel (`frontend`) → **Root cause**: check memakai parameter contoh template, bukan parameter yang benar-benar dikirim pemanggil. → **Invariant Rule**: uji baris log dengan nilai yang sama seperti yang dikirim runtime, dan bandingkan dengan `template.text` yang diisi nilai itu — bukan dengan sampel template.

- **[26-10-22 · Atribusi penolakan reviewer]**: Alasan reviewer adalah prosa bebas; mencocokkannya ke bullet `review` dengan satu kata membuat "the diff does not support it" menghukum aturan yang salah → **Root cause**: ambang kecocokan tidak ada, dan stemming sederhana (`idempotent` vs `non-idempotent`) tidak menangkap variasi kata. → **Invariant Rule**: butuh minimal dua kata signifikan yang sama (atau substring untuk kata ≥6 huruf) sebelum sebuah penolakan diatribusikan ke aturan; yang tidak lolos dihitung `unmatched`, bukan dipaksa, dan urutan ranking harus deterministik (count lalu urutan pak).

- **[26-10-22 · Nama pak di dua tempat]**: Label pak hidup di `rolePacks.ts` untuk model, sedangkan kartu dan tab Playbook butuh nama yang bisa diterjemahkan; menyalinnya begitu saja membuat dua sumber kebenaran yang bisa menyimpang → **Invariant Rule**: nama UI adalah baris kamus ber-key per id (`shared/packs.ts`), dan `check:playbook` menuntut kolom Inggris-nya sama persis dengan `label` pak di server serta setiap id punya barisnya.
