# Memory

### 🧠 Learned Invariants & Failure Post-Mortems

- **[26-10-20 · Scene / character pose]**: Workers rendered standing next to their desks → **Root cause**: new characters spawned at the lounge and walked to their station, but the walk step is frame-rate bound (`WALK_SPEED * delta` with `delta` capped at 0.06), so on a software renderer they never arrived and `setSitting` was only called inside the arrival branch. → **Invariant Rule**: spawn a character at its destination station on first sync, and never let pose state (sitting/walking) depend on a movement loop that may not converge.

- **[26-10-20 · Scene / tick]**: Animation stuttered and walking stalled on slow tabs → **Root cause**: `delta` was clamped to 0.06 s, so a 3 fps frame advanced only 0.06 s of the world per frame. → **Invariant Rule**: clamp frame delta to the largest value that still prevents teleporting (0.15 s here), and keep time-scaled motion out of the clamped region.

- **[26-10-20 · Web search]**: `web_search` returned zero results on every query → **Root cause**: `lite.duckduckgo.com` answers datacenter IPs with HTTP 202 and a bot-challenge page, so the `result-link` selector never matched. → **Invariant Rule**: treat an empty parse as a provider failure, not an answer, and chain keyless providers (DuckDuckGo HTML POST, then Bing RSS) before surfacing an error.

- **[26-10-20 · Tool loop / model protocol]**: The model emitted native tool-call markup instead of the JSON action the prompt asked for, so actions never ran → **Root cause**: the provider speaks OpenAI function calling; instructing JSON in the prompt fights the wire protocol. → **Invariant Rule**: advertise real `tools` schemas and consume `tool_calls` deltas; keep the JSON-action parser only as a fallback for endpoints that reject `tools`.

- **[26-10-20 · Sandbox]**: Allowlisted binaries could still be pointed outside the workspace → **Root cause**: the command allowlist validated the binary but not its arguments, and `cwd` is not a boundary. → **Invariant Rule**: validate every argument token (`..` hops, absolute paths) against the workspace root in addition to the binary allowlist, and never claim a shell is jailed when it is only checked.

- **[26-10-20 · Mission roll-up]**: The lead started reconciling while a queued subtask was still running → **Root cause**: `create_task` recorded the *immediate* task as parent, so work a subtask delegated lived one level below the mission and never counted in "is the team done?". → **Invariant Rule**: roll delegated work up to the mission root (`mission ? taskId : parent.parentId ?? taskId`), and always derive "everyone finished" from that root.

- **[26-10-20 · Client bootstrap]**: The office sat on "Connecting…" forever after one failed `/api/session` → **Root cause**: bootstrap fetched once, swallowed the error, and then subscribed; nothing retried and the empty state rendered as a permanent loading state. → **Invariant Rule**: subscribe to the stream that carries a full snapshot *first*, and give the initial fetch bounded retries — a UI must never have a terminal loading state.

- **[26-10-20 · Verification tooling]**: `pkill -f "server/src/index.ts"` killed the very shell running the command, silently aborting a verification chain → **Root cause**: `pkill -f` matches full command lines, including the shell whose `-c` string contains the pattern. → **Invariant Rule**: when killing by pattern, use a regex that cannot match its own command line (`src/inde[x].ts`), or kill the listener PID from `ss -ltnp`.

- **[26-10-20 · Completion gate]**: A task showed `done` in the UI while its checks were still running → **Root cause**: the `complete_task` handler flipped the status first and the runtime ran verification afterwards, so every observer (board, CLI poll loop) saw success before validation finished. → **Invariant Rule**: run a gate *before* mutating the state it guards; never let an observable transition happen ahead of its validation.

- **[26-10-20 · `speak` tool]**: A mission that had built the whole site ended as `blocked` → **Root cause**: `speak` returned `followUp: false`, so a decorative speech bubble terminated the turn and the still-`doing` task fell into the blocked branch. → **Invariant Rule**: only `complete_task` may end a task turn; cosmetic tools must keep the loop alive whenever a task is attached.

- **[26-10-20 · `read_file` window]**: `read_file` answered with a single line → **Root cause**: a `limit` of `0` was clamped up to 1 instead of falling back to the default window. → **Invariant Rule**: treat zero/negative paging values as "use the default", and clamp only after the default has been chosen.

- **[26-10-20 · CLI boot / session readiness]**: `aegisxworker "…"` ran the mission in demo mode even though a valid key was loaded → **Root cause**: `GET /api/session` answers as soon as Express listens, but the boot-time `connect()` is awaited afterwards, so the first snapshot still reports `configured: false` / `demoMode: true` and the CLI trusted it. → **Invariant Rule**: any consumer that branches on connection state must poll until `settings.configured` flips (bounded timeout), never branch on the first successful HTTP response.

- **[26-10-20 · CLI config]**: The launcher did not see `OFFICE_API_KEY` from `.env` → **Root cause**: `--env-file` is passed to the *child* server process, so the parent CLI's `process.env` stays empty. → **Invariant Rule**: resolve config in one place — the CLI only decides flags, the server owns env loading; the CLI detects a key with `existsSync('.env')` instead of reading `process.env`.

- **[26-10-20 · Verification]**: Background restarts silently failed and the old process kept serving → **Root cause**: `kill <wrapper pid>` left the real `node` child alive, so the new server died with `EADDRINUSE` while tests ran against stale code. → **Invariant Rule**: confirm the listener PID via `ss -ltnp` after every restart, and verify the new code path (e.g. a changed log line) before trusting a green test run.

- **[26-10-21 · Token meter]**: Per-task spend would have drifted from per-agent spend if each side kept its own counter → **Root cause**: `tokensUsed` was written by two call sites (real turn, demo turn) and a task had no counter at all, so any new call site could book a turn on one side only. → **Invariant Rule**: book usage in exactly one place (`OfficeStore.recordUsage`) that moves the worker *and* the task together, and derive every roll-up (mission, summary, UI) from that single field.

- **[26-10-21 · Mocked multi-agent test]**: A scripted lead wrote the deliverable instead of delegating → **Root cause**: the mock matched a substring of the mission *detail* (`Build the UI and the API…`) rather than the subtask title on the brief's first line. → **Invariant Rule**: when scripting a model, branch on the exact brief field you control (`Task: <title>` first line), never on a substring that the operator's prompt can also contain.

- **[26-10-21 · Mission restore]**: A restored board could have looked alive while nothing was running → **Root cause**: `doing` is a statement about a live process, and persistence alone brings the label back without the process. → **Invariant Rule**: on boot, settle every `doing` task to `blocked` with a reason before serving the first snapshot; never auto-run a restored task (that silently re-bills) and never leave a worker marked busy.

- **[26-10-21 · Shared test state]**: Two suites chained in one shell passed alone and failed together → **Root cause**: both inherited the same `OFFICE_STATE_DIR`, so the second suite restored the first one's board. → **Invariant Rule**: every suite that boots the office must own a fresh state directory; shared persistent state turns independent tests into an order-dependent chain.

- **[26-10-21 · Per-step cost]**: Attributing token cost to individual tool calls would have inflated every total → **Root cause**: an endpoint bills a model round trip, and one round can emit several tool calls, so splitting or repeating the round's usage per call double-counts. → **Invariant Rule**: cost the *round*, log one step line per round, and assert in a check that the step bills sum to the task total.

- **[26-10-21 · History roll-up]**: A daily cost total could count a subtask twice → **Root cause**: the history walked every finished task, while a mission's total already includes its subtasks. → **Invariant Rule**: group by the root that owns the spend (mission root, or a standalone task), and skip any task with a `parentId` when building totals.

- **[26-10-21 · Panel tabs]**: A hidden `[hidden]` tab kept rendering its flex layout → **Root cause**: a class rule (`display: flex`) outranks the user-agent `[hidden] { display: none }`, so the Activity list stayed visible behind the Costs tab. → **Invariant Rule**: any element toggled by the `hidden` attribute that also sets `display` needs its own `[hidden] { display: none }` rule.

- **[26-10-21 · Verification harness]**: The README's main regression commands pointed at `/tmp/pw/*.mjs` and those files were gone, so the gate, checkpoint, tool jail and renderer had no re-runnable proof → **Root cause**: the harness was written in a scratch folder instead of the repo, so no path in the documentation was tied to a file that survives a temp cleanup. → **Invariant Rule**: every command a doc tells someone to run must live under `scripts/` behind an npm script; a harness in `/tmp` is a scratch run, not coverage — and check the *failure* paths, since the happy path is already exercised by the live-server run.
